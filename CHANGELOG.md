# Changelog

## [1.7.6] - 2026-08-16 - Color depth, effects, image mode and rotation tools in the main viewer toolbar, image adjustments window removed

- Added a color depth tool to the main viewer's floating toolbar: choose 32-bit, 24-bit, 8-bit, or 1-bit with one click, with an option to restore the page's original depth at any time. The current format is always shown for reference. The old Color Depth section in the image adjustments window has been removed now that this tool lives in the main viewer's toolbar instead.
- Added an effects tool to the main viewer's floating toolbar: apply Grayscale, Sepia, or Invert colors with one click, with an option to restore the page's original look at any time. The old Effects section in the image adjustments window has been removed now that this tool lives in the main viewer's toolbar instead.
- Added an image mode tool to the main viewer's floating toolbar: switch the page between RGB, RGBA, grayscale, grayscale with transparency, CMYK, pure black and white, or 256-color palette with one click, with an option to restore the page's original mode at any time. This was the last setting still living in the separate image adjustments window.
- Removed the now-empty image adjustments window entirely, along with its "Image adjustments..." entry in the Images menu, the right-click menu, and the icon column. The shared image-editing engine behind it and every tool in the main viewer's toolbar was renamed from `adjustments_processing_qt.py` to `image_processing_qt.py`, since it no longer has anything to do with that removed window.
- Added a rotation tool to the main viewer's floating toolbar: rotate the current page left or right, or flip it horizontally or vertically, without leaving the viewer. These same actions were already available from the icon column, the menu bar, and the right-click menu for a whole selection of pages at once in the mosaic view — they remain there unchanged, this is simply an additional, quicker way to reach them for the page currently being read.
- Updated the help window's "Viewer" section to describe the floating toolbar and every tool it now offers, and removed its separate "Crop" and "Image adjustments" sections (both folded into "Viewer"), reflecting the toolbar work from this version and the last few.
- REPOSITORY ONLY: Removed the now-stale `adjustments-panel` Claude Code skill (84 total), which documented the removed image adjustments window.
- Fixed some error messages in the main viewer appearing centered on the whole window instead of on the panel that triggered them.

## [1.7.5] - 2026-08-15 - Compression, levels, transparency and shape drawing tools in the main viewer toolbar, floating Apply/Cancel buttons overhaul, Undo/Redo and .ico editing fixes

- Added a compression (JPEG quality) tool to the main viewer's floating toolbar (10th tool to move there): works the same way as the sharpness/brightness tools (single slider, live preview while dragging, applied on release, stays on the applied value afterward). Unlike the other adjustment tools, its icon is grayed out (with an explanatory tooltip) whenever the page currently shown isn't a JPG, WEBP, or AVIF image, since compression only makes sense for those formats. The old Compression section in the image adjustments panel, along with its dedicated fullscreen preview window, has been removed now that this tool lives in the main viewer's toolbar instead.
- Added a black/white levels tool to the main viewer's floating toolbar (11th tool to move there): two eyedroppers (click a pixel on the page to set it as pure black or pure white) plus four sliders (black point, gamma, white point, and threshold), each labeled and with its own explanatory tooltip, spread across two rows to keep the panel readable : one row for the sliders, one for the eyedroppers and the "Auto" button. Works the same way as the other slider-based tools otherwise (live preview, applied on release or eyedropper click, stays on the applied value afterward). The old Levels section in the image adjustments panel, along with its dedicated fullscreen pipette-based preview window, has been removed now that this tool lives in the main viewer's toolbar instead.
- Added a transparency tool to the main viewer's floating toolbar (12th tool to move there): click a color on the page to make it transparent, either just the connected area of similar color around the clicked spot ("Area") or every matching pixel across the whole image ("Global"), with a tolerance slider controlling how close a color needs to be to count as a match. Several clicks can be made before applying them all at once with the toolbar's "Apply" button. Only available for PNG, WebP, ICO, and AVIF images, since other formats can't store transparency; the icon is grayed out otherwise. The old Transparency section in the image adjustments panel, along with its dedicated fullscreen preview window, has been removed now that this tool lives in the main viewer's toolbar instead — completing the move of every adjustment tool out of that separate window.
- Added a shape-drawing tool to the main viewer's floating toolbar: draw ellipses, rectangles, rounded rectangles, lines, and arrows directly on top of a page by dragging with the mouse. Pick the outline thickness and a single color (used for both the outline and, optionally, the fill) from the tool's panel, with an eyedropper to pick up a color straight from the page itself. Once drawn, a shape can be resized from its corner/edge handles, dragged to a new position, rotated from a dedicated handle above it, or nudged one pixel at a time with the arrow keys; Delete/Backspace removes the selected shape (or cancels a shape still being drawn), same as Escape. Several shapes can be drawn on the same page before applying them all at once with the toolbar's "Apply shapes" button, which turns green as soon as there's something to apply and stays greyed out otherwise.
- Added a "Cancel" button next to "Apply" for the crop, straighten, text, shape, and transparency tools: discards all of that tool's unapplied work on the current page in one click (turning red once there's something to discard, greyed out otherwise), the same thing Escape already did, now also reachable without the keyboard.
- Fixed Undo/Redo (keyboard shortcuts and toolbar buttons alike) being usable while one of the tools above still had unapplied work on the current page, which could let an undo/redo silently clash with that pending work once it was later applied. Undo/Redo now does nothing while such work is pending, the same as when there's simply nothing left to undo/redo.
- The crop, straighten, and text tools' "Apply" button now behaves the same way as the new shape tool's: it stays visible right under the toolbar the whole time the tool is active (green once there's something to apply, greyed out otherwise), instead of sitting at the bottom of the screen and only appearing once something was drawn.
- Fixed the toolbar's floating "Apply" button occasionally staying on screen by itself after the toolbar auto-hid, and the auto-hide countdown not pausing while hovering over that button the way it already did over the toolbar itself.
- Fixed every slider-based adjustment tool added to the main viewer's toolbar so far (sharpness, adaptive sharpness, brightness/contrast, saturation, color removal, compression, and the new levels tool) resetting the image's pan position back to center as soon as an adjustment was applied, if the page had been zoomed and panned beforehand.
- Fixed clicks on some of the toolbar's floating option panels occasionally reaching through to the page underneath instead of staying on the panel, and the mouse cursor sometimes keeping an eyedropper/tool shape while hovering a panel or the Apply/Cancel buttons instead of turning back into a normal pointer there.
- Fixed editing a `.ico` page (crop, rotate, any adjustment tool...) silently turning it into a plain PNG instead of keeping it as a proper multi-resolution icon file. Editing one now keeps every resolution size it originally had.
- Renamed the source file and internal classes backing the sharpness/adaptive sharpness tool (`adjustments_tool_qt.py` → `sharpness_tool_qt.py`) to match every other main-viewer-toolbar tool's own dedicated module naming, its previous name being a leftover from before those tools each got their own separate file.
- Fixed some of the main viewer's toolbar tools misbehaving when used in double-page or continuous reading mode. Selecting any tool there now switches back to single-page mode first.
- REPOSITORY ONLY: Added a new Claude Code skill (`draw-shapes`, 85 total) documenting the shape-drawing tool above.

- Fixed the mosaic sometimes not showing a page's latest look right after an Undo/Redo done from the main viewer.
- Fixed the mosaic's transparency checkerboard, shown behind images with an alpha channel, incorrectly filling the entire thumbnail frame instead of only the image's own bounds : whenever an image's proportions didn't match the thumbnail frame's, the checkerboard used to extend past the image's actual shape into the surrounding padding.

- Fixed web import missing most (or all) images on pages that generate their `<img>` tags with JavaScript instead of writing them directly in the page's HTML. Only images already present in the raw HTML used to be picked up. Importing a page now also scans its `<script>` content for common JavaScript loop patterns that build image paths (`for` loops and setTimeout-driven ones alike) and resolves them directly, without ever running the page's JavaScript. Also fixed image URLs containing spaces (e.g. `Fantastic 09 01.jpg`) failing to download outright, added a couple of automatic retries for images that fail on a transient network error, and fixed the red "Analyzing page..."/"Downloading..." progress text overlapping the mosaic's own "Drop files here" placeholder text while the canvas was still empty.

## [1.7.1] - 2026-08-09 - Automatic deskew, scan settings now remembered between sessions

- Added automatic deskew: detects and corrects the skew of a scanned page (e.g. a book photographed slightly askew) and straightens it in place, filling the resulting empty corners in white. This is a fully automatic counterpart to the existing manual straightening tool, both remain available and neither replaces the other. The "Straighten image" icon/menu entries are now split into "Straighten manually..." (the existing tool, unchanged) and "Straighten automatically" (the new one); the icon column button switches between the two modes via right-click, the same way the renumbering button already does, with a tooltip showing the current mode. Detection uses OpenCV's Hough line transform on the image's dominant edges; if no reliable line consensus is found, the image is left untouched and listed as a failure in a final summary window (successes/failures count, with the list of failed file names). Works on a multi-image selection at once, applying each image sequentially with a single combined undo/redo step for the whole batch : same mechanism as rotation/mirroring. Requires a new dependency, `opencv-python`. The "Reset to defaults" command/tooltip now also mentions resetting this mode back to manual.
- The scan dialog now remembers the last scanner, resolution (DPI), and color mode you chose, and proposes them again automatically the next time you open it — previously it always reset to the first detected device and 300 DPI. The help window's "Scan an image" section was updated to mention this.

## [1.5.10] - 2026-07-15 - Viewer zoom overhaul, webtoon reading mode, recent files fixes, duplicate-pages window group selection, random crash fix (Pages table), Qt runtime update

- Reworked zoom in the image viewer: it no longer recenters the image on every zoom step, panning (right-click + drag) is now preserved while zooming instead of being reset; the zoom ceiling was raised from 500% to 1000%; and "100%" now means the image's actual pixel size (1 image pixel = 1 screen pixel) instead of a multiple of the fit-to-window size, which used to silently upscale far beyond the image's real resolution at high zoom levels. Zooming is also now essentially instant at any level, including 1000%: the viewer used to re-resize the full-resolution image with PIL on every single zoom step (CPU-bound, and increasingly expensive the higher the zoom); it now uploads the image once and lets Qt stretch it on screen instead, the same lightweight approach already used by the crop/straighten/clone-stamp/text viewers. Ctrl+0 now fits the current page to the window (its previous behavior moved to Ctrl+1, which resets zoom to 100%) — also added to the crop, straighten, clone-stamp, and text viewers, which previously only had Ctrl+0 for a 100% reset and no way to fit the window; those same four viewers also gained the Ctrl+Plus/Ctrl+Minus zoom shortcuts already available in the main viewer, matching their existing on-screen +/- zoom buttons. The main viewer's right-click menu and the help window's "Viewer" and "Keyboard shortcuts" sections were updated to match. Also fixed the zoom level and its on-screen percentage both being wrong the moment a page is first opened (computed against the window's not-yet-final size, and the label separately stuck showing "100%" regardless of the actual computed value).
- Added a fourth main viewer reading mode, "Webtoon" (same `D` key), for vertical images: capped-width zoom (900px) instead of fit-to-window, mouse wheel scrolls the page and turns it at the top/bottom edge, thin scroll-position indicator on the right edge.
- Fixed the transparency checkerboard background being generated one pixel at a time, causing multi-second freezes on very large images (e.g. tall webtoon pages); now tiled instead.
- Fixed newly created CBZ files not being added to the recent files list in two cases: creating a CBZ from images loaded without a source archive ("Create CBZ archive"), and exporting the current page selection to a new CBZ file ("Save selection as CBZ"). Both now appear in the recent files menu right after creation, like any other opened or saved file.
- Added a "Select group" / "Deselect group" button pair to each group's header in the duplicate pages window, to check or uncheck every page of that specific group in one click instead of one by one; the "Delete selection" button at the bottom now greys out whenever nothing is checked.
- Updated the bundled Qt runtime (PySide6/shiboken6) from 6.10.2 to 6.11.1.
- Fixed a random full-application crash (Windows access violation, no error message) that could strike during or shortly after operations rebuilding the page list many times in a row — typically deleting duplicate pages group by group and then walking the undo/redo history, often detonating on a mouse movement moments later. Root cause: the Pages table of the metadata panel disposed of its background build thread without waiting for it to fully finish (the thread signals its result on its very last instruction, so the disposal could destroy it while still running — undefined behavior in Qt that silently corrupts memory and crashes much later, anywhere). ## [1.3.6] - 2026-06-21 - Security fixes and UI improvements

The extension mismatch dialog now uses a single generic message key with `{real}` and `{declared}` parameters, replacing four format-specific keys.
- Added CBT (TAR) support. CBT archives (uncompressed, gzip, and bzip2) can now be opened. The format is read-only: saving produces a CBZ, as with CBR and CB7. Misnamed CBT files (e.g. a TAR renamed to .cbz) are detected and the rename dialog is shown. CBT files are included in all open/drop/merge file filters. ComicInfo.xml is read from CBT archives.
- Improved CBR→CBZ batch conversion. Archive format is now detected by magic bytes instead of try/except. Misnamed CBR files that are actually ZIP, 7z, or TAR archives are renamed to the correct extension (.cbz, .cb7, .cbt) instead of being reported as errors. Renamed files are logged with before/after filenames. The summary dialog shows a separate count for each renamed format and a link to the log whenever there are renamed files or errors.
- Added CB7→CBZ batch conversion. All .cb7 files in a folder (recursively) are extracted and repackaged as CBZ. Misnamed CB7 files that are actually ZIP, RAR, or TAR archives are renamed to the correct extension (.cbz, .cbr, .cbt). A log is created when files are renamed or errors occur. ## [1.0.5] - 2026-04-03 - Bug fixes and performance improvements

- Fixed a multi-second delay when opening a CBZ archive. The loader was calling `testzip()` on the archive before reading any images, which read and verified the CRC of every file in the archive before loading could begin. This check has been removed: individual read errors are already caught during loading.
- Fixed a bug where lazy-loading a corrupted image would spam the console with the same error message on every repaint. The entry is now marked `is_corrupted = True` on the first failure so subsequent load attempts are skipped immediately.
- Code cleanup: removed dead tkinter remnants from the Qt codebase. The `regenerate_thumbnail` function in `entries.py` was a no-op (all branches only set `entry["tk_img"] = None`) and has been deleted along with all its call sites. The `tk_img` and `name_var` keys, which were initialized to `None` and never read, have been removed from entry creation (`entries.py`, `image_ops.py`) and from cleanup loops (`file_close_qt.py`, `panel_widget.py`). The unused `state._dir_tk_imgs` attribute has also been removed.
- Fixed a bug where dragging a thumbnail upward out of the mosaic area (onto the tab bar, menu bar, or header strip) would import a copy of the image into the mosaic. The `MainWindow` drop handler was accepting the drop because the drag payload includes a temporary CF_HDROP file intended for drag-out to the file explorer. The handler now ignores any drop whose MIME data contains the internal `application/x-mosaicview-indices` format.
- All save dialogs (Save As, Save Selection as CBZ, Export Selected Pages, Create CBZ from Images, Apply and Create CBZ from CBR/PDF) now remember the last directory used and reopen there on the next call.
- Resize, Convert, and Adjustments actions no longer block when the selection contains non-image files (e.g. .nfo, .xml). Non-image files are silently ignored and the action runs on the image files only. The error is only shown if the selection contains no images at all.
- Fixed a freeze after cropping an image. The crop operation was emitting `metadata_signal`, which triggered a full rebuild of the metadata panel including all page rows. Since only `ImageWidth`, `ImageHeight`, and `ImageSize` change after a crop, the signal is now `metadata_pages_signal`, which updates only those values in place.
- After cropping, the mosaic now updates only the thumbnail of the cropped image instead of rebuilding the entire scene.
- Reduced the freeze after flattening a directory structure. The mosaic is now updated immediately.
- Fixed a freeze after resizing images. The same issue as the crop freeze: `metadata_signal` was emitted at the end of the operation, triggering a full rebuild of the metadata panel. The signal is now `metadata_pages_signal`. Additionally, the mosaic now updates only the thumbnails of the resized images instead of rebuilding the entire scene.
- Fixed transparent images (PNG, GIF, etc.) not showing a checkerboard background in the image viewer. The viewer was compositing the image onto a black background instead. Images with an alpha channel now display with the same light/dark checkerboard used in the mosaic and the transparency viewer in Adjustments.
- Extended the checkerboard background to all viewers and previews that display images with an alpha channel: the brightness, contrast, sharpness, saturation, adaptive sharpness, and color removal viewers in Adjustments, and the small preview thumbnail in the Adjustments dialog. Several of these viewers lost the alpha channel during PIL processing (e.g. `ImageEnhance.Brightness` on an RGBA image returns RGB); the alpha is now recovered from the original image before compositing onto the checkerboard. The preview thumbnail in the Adjustments dialog also composites after resizing to ensure the checkerboard squares remain a consistent size regardless of the source image dimensions. The ICO creator source image viewer (crop phase) also now shows a checkerboard for transparent sources.
- Replaced the page list in the metadata panel with a `QTableView` backed by a background thread model builder. The previous implementation created one widget row per page on the UI thread in batches, blocking the interface for several seconds on large comics. The table is now built off the UI thread and displayed instantly when ready. Columns are sortable by clicking the header. File sizes are displayed in human-readable units (B, KB, MB).
- Fixed a freeze when opening the image viewer after converting all pages of a large comic and deleting the originals. The viewer's page-mode detection (`_get_all_ratios`) had to load all converted images via PIL because the converted entries did not have their `img_width`/`img_height` fields set. These fields are now populated in `convert_image_data` directly from the converted image, so subsequent viewer opens are instant.
- Fixed a bug where clicking the close button after converting images and then opening and closing the image viewer would close the application without showing the save/discard dialog. The `_NameTextEdit.focusOutEvent` handler in the mosaic was resetting `state.modified` to `False` when restoring an empty name field to its original value — this reset was global and incorrect. It has been removed.
- Fixed a bug where clicking the close button, choosing to stay (Cancel), and then clicking close again would close the application immediately without showing the dialog. The `_close_event_handled` guard flag was not reset to `False` when the user cancelled, so the second close event was accepted unconditionally.
- Fixed a bug where undoing a page deletion did not update the metadata panel. After undo, `images_data` was correctly restored to its previous state, but `sync_pages_in_xml_data` was not called, so the `<Pages>` section in `comic_metadata` still reflected the post-deletion count. The sync is now performed during state restoration in `restore_state_qt`, followed by a full metadata panel refresh.
- The metadata panel now responds to the Home and End keys to scroll to the top or bottom of the panel.
- Fixed the progress overlay (conversion percentage, cancel button) scrolling with the mosaic instead of staying fixed on screen. Both overlays were `QGraphicsItem` elements added to the scene and therefore moved with it. They are now `QLabel` widgets parented to the viewport, so they remain centered on screen regardless of scroll position.
- Fixed a bug where a `.cb7` file that was actually a ZIP or RAR archive would open silently without prompting to rename it. Since 7-Zip can read ZIP and RAR files transparently, the format detection never fell through to the rename dialog. The file's magic bytes are now checked before invoking 7z, so misnamed archives are correctly detected and the rename dialog is shown.

## [1.0.4] - 2026-03-31 - Technical updates

- Fixed a bug where resizing images in a CBZ containing a `ComicInfo.xml` with a `<Pages>` section would cause the application to become unresponsive for the entire duration of the operation. After each resized image, the XML metadata was updated and a signal was emitted from the worker thread, triggering a full rebuild of the metadata panel UI on each image. On a 110-page file this resulted in 110 queued UI rebuilds that could take over an hour to drain. The signal is now suppressed during the resize loop and emitted once when the operation completes.
- Fixed a long freeze at the end of a resize operation. The worker was unnecessarily invalidating the cached thumbnail pixmap for each resized image, forcing `render_mosaic` to rebuild all thumbnails from scratch in the UI thread. Since resizing does not change the visual appearance of thumbnails, the cache is now preserved.
- Fixed a long freeze after the mosaic was refreshed at the end of a resize operation. The metadata panel was doing a full rebuild of all its widgets (including all page rows) in response to the metadata signal. After a resize, only the `ImageWidth`, `ImageHeight`, and `ImageSize` values change — the panel now updates only those values in place.
- Fixed a bug where dragging a WebP image from a web browser would incorrectly store it with a `.jpg` extension. Chrome silently transcodes images to WebP when dragging them, while keeping the original filename. The actual file format is now detected from the file content and the extension is corrected accordingly.
- The file extension label in the mosaic now appears in red for image formats other than JPG, PNG, GIF, and BMP (e.g. WEBP, TIFF, ICO). This is a warning indicator: these formats may not be readable by older CBZ/CBR readers. MosaicView itself handles them normally. Non-image files (e.g. `.xml`, `.nfo`) are not affected.
- Fixed the "Conversion complete" dialog where the three action buttons were too narrow to display their text correctly. The dialog width was increased from 540px to 620px.
- On startup, stale `_MEI*` temporary directories left behind by PyInstaller after a crash are now silently deleted. Directories still locked by another active instance are left untouched. If a directory cannot be deleted after a crash, a Windows restart may be required to release the lock.
- Fixed a bug where dropping multiple archives onto an empty canvas would not show the source archive name in the thumbnail tooltips. Only the merge path (dropping onto an already-open comic) correctly set the provenance. The initial multi-load path now sets it as well.
- In split view, resizing the window now preserves the ratio between the two panels instead of forcing a 50/50 split. Double-clicking the separator resets it to 50/50.
- Reorganized the right-click context menus. Commands that act on a selection (Save selection as CBZ, Export selected pages, Print selection, Copy, Cut, Delete, Deselect) have been moved from the canvas context menu to the thumbnail context menu. Commands that act on the archive as a whole (Renumber pages, Flatten directories) have been moved from the thumbnail context menu to the canvas context menu. The Show/Hide icon column command is now the first item in the canvas context menu.
