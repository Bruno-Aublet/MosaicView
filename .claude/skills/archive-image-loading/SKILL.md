# Chargement d'archives et d'images isolées — MosaicView

Point d'entrée de **toute** donnée qui finit dans `state.images_data` (donc dans la mosaïque) : ouverture d'une archive CBZ/CBR/CB7/CBT/EPUB, ajout d'images isolées, fusion d'une archive dans une session déjà ouverte. Ne couvre pas les formats qui ont leur propre pipeline séparé (PDF — voir skill `pdf-loading`, seul format jamais ouvert dans le process Qt principal — et l'import ComicVine/batch qui réutilise ces mécanismes sans les redéfinir).

## Fichiers clés

- **`modules/qt/archive_type_detector.py`** — `detect_archive_type(filepath)` : détection du **format réel** par magic bytes (pas par extension). Fonction pure, ~60 lignes, aucune dépendance Qt.
- **`modules/qt/archive_loader.py`** — cœur du chargement d'archives : `LoadWorker` (QThread), `ArchiveLoader` (orchestrateur QObject côté UI), dialogues associés (`ExtensionCorrectionDialog`, `_MessageDialog` — la fenêtre « Fichiers ignorés »). Contient aussi les wrappers du binaire 7-Zip embarqué (`_get_7z_exe`, `_list_7z_files`, `_read_7z_file`) puisque `zipfile`/`rarfile`/`tarfile` stdlib ne couvrent pas le 7z, et les lecteurs de membres communs à tous les chemins de lecture (`_zip_member_reader`, `_tar_member_reader`, `_tar_info_read`, `_rar_read`, limite `MAX_MEMBER_SIZE`, voir « Lecture des membres »).
- **`modules/qt/entries.py`** — `create_entry()` : construit une **entrée** de `images_data` à partir de bytes bruts (décodage PIL, détection GIF animé, hash MD5, dimensions...) — le point de passage obligé, qu'on charge depuis une archive, un fichier isolé, ou un TIFF multi-pages. Aussi : `create_entry_from_file()`, `create_entries_from_tiff()`, et le lazy-loading (`ensure_image_loaded`/`free_image_memory`/`get_gif_frame`).
- **`modules/qt/panel_widget.py`** — `_ImageLoadWorker` (QThread pour les images isolées, classe locale à ce fichier), `PanelWidget._load_files()` (routeur central : dispatch par extension vers archive/PDF/image), `_start_image_load()` (câblage UI du worker d'images).
- **`modules/qt/import_merge_qt.py`** — `ImportMergeWorker`/`import_and_merge_archive()` : fusionne une **deuxième archive** dans la session déjà ouverte (pas un nouveau chargement qui réinitialise `images_data`) — réutilise `create_entry`, `_list_7z_files`/`_read_7z_file` du loader.
- **`modules/qt/mosaic_canvas.py`** — `build_qimage_for_entry()` : appelé juste après `create_entry()` par tous les chemins de chargement pour préconstruire le cache vignette en arrière-plan (voir skill `mosaic-thumbnails`).
- **`modules/qt/comic_info.py`** — `sync_comic_metadata()` : métadonnées lues dans le ComicInfo.xml du document chargé, appelée par `ArchiveLoader._on_finished` juste après le chargement ; `name_incoming_comic_infos()` : un seul ComicInfo.xml par document (voir skill `comicinfo-metadata-editor`).

## Vue d'ensemble — trois familles de chargement

| Famille | Déclencheur | Réinitialise `images_data` ? | Classe worker |
|---|---|---|---|
| **Ouverture d'archive(s)** | Premier fichier CBZ/CBR/CB7/CBT/EPUB ouvert dans un panneau vide | Oui | `LoadWorker` (`archive_loader.py`) |
| **Fusion d'archive** | Glisser/ouvrir une archive alors qu'un comic est déjà affiché | Non — ajoute à la suite | `ImportMergeWorker` (`import_merge_qt.py`) |
| **Ajout d'image(s) isolée(s)** | Fichiers image/`.nfo`/`.txt`/`.xml` ouverts ou droppés (panneau vide **ou** déjà ouvert) | Non si déjà ouvert, sinon initialise | `_ImageLoadWorker` (`panel_widget.py`) |

Le **PDF** est une quatrième famille, chargé via un process séparé dédié (un par chargement, jamais partagé) — hors périmètre de ce skill, voir skill `pdf-loading` pour l'architecture complète.

## Le routeur central — `PanelWidget._load_files()` (`panel_widget.py`)

Point d'entrée unique quel que soit l'appelant (ouverture menu, drag & drop, fichier récent, Bibliothèque) :

0. **Chargement d'archive ou de PDF déjà en cours dans ce panneau** (`_replacing_load_in_progress()` : worker de `ArchiveLoader` ou de `PdfLoader`, ou process PDF de l'étape du dialogue DPI) → les chemins sont **mis en attente** dans `_pending_load_paths` (avec le `doc_generation` courant et les options d'appel) et la fonction s'arrête là. `_on_loading_finished` appelle en dernier `_run_pending_loads()`, qui les rejoue par `_load_files` : en fusion si le chargement a abouti (le document est ouvert), ou ouverts dans le panneau resté vide s'il a échoué ou été annulé. Les chargements PDF qui échouent sans passer par `_on_loading_finished` (erreur, mot de passe, PDF vide, choix de la résolution annulé) appellent `_run_pending_loads` par `PdfLoader._after_failed_load` (skill `pdf-loading`). Ne sont abandonnés que les fichiers d'un document fermé entre-temps (`doc_generation` changé ; `force_close_file` vide aussi la file, comme la fermeture du double panneau). Les lots sont triés **avant** la boucle : le premier lot rejoué peut lancer un nouveau chargement (panneau vide), qui change `doc_generation` ; les suivants sont alors remis en attente par `_load_files` pour ce nouveau document. **Piège** : abandonnés, ces fichiers disparaissaient sans aucun message. Tout appel de `_load_files` hors chargement vide la file.
1. Sépare `paths` par extension : `cbz_files` (`.cbz`/`.cbr`/`.cb7`/`.cbt`/`.epub`), `pdf_files` (`.pdf`), `image_files` (liste `IMAGE_EXTS`), `annex_files` (`.nfo`/`.txt`/`.xml`), `other_files` (reste → avertissement "fichiers non supportés", rien n'est chargé pour eux).
2. `already_open = st.current_file is not None or bool(st.images_data)` — **la variable qui décide tout le comportement** : premier chargement (réinitialise) vs ajout dans une session existante (fusionne).
3. PDF présent : si déjà ouvert → dialogue de choix de DPI puis `import_and_merge_pdf` ; sinon → `reset_history` + `self._pdf_loader.load(...)`.
4. Archives présentes : si déjà ouvert → **une fusion par fichier**, dans l'ordre de tri naturel, via `_import_merge_archive()` (donc `N` fusions séquentielles si `N` archives droppées en même temps) ; sinon → `reset_history` + `self._loader.load(cbz_sorted)` (un seul chargement multi-archives, voir `load_multiple_archives`).
5. Images/annexes présentes (peuvent coexister avec une archive/un PDF dans le même appel) : `_start_image_load(...)`.

**Piège** : PDF, CBZ et images peuvent tous être présents dans le même appel à `_load_files` (ex. drop mixte) — les trois branches s'exécutent, pas de `elif` entre PDF et CBZ pour les images (`if image_files or annex_files:` est un bloc séparé, toujours évalué). Vérifier ce comportement avant de le changer si une tâche touche à l'ordre de priorité entre types de fichiers.

## Chargement d'archive — `ArchiveLoader` / `LoadWorker`

### `ArchiveLoader` (QObject, un par panneau, construit dans `PanelWidget.__init__`)

Orchestre le worker et l'affichage pendant le chargement :
- `load(filepaths)` : **réinitialise entièrement `state`** (`images_data=[]`, `selected_indices.clear()`, `comic_metadata=None`, `merge_counter=0`, etc.) et incrémente `state.doc_generation` (nouveau document, voir skill `file-close`) avant même de lancer le thread — un appel à `ArchiveLoader.load()` n'est **jamais** une fusion, contrairement à `import_merge_qt`.
- Affiche un texte rouge centré sur le canvas avec pourcentage (`_show_loading_text`, réutilise `canvas_overlay_qt.show_canvas_text` — pas de `QProgressDialog` ; voir skill `canvas-overlay-progress` pour le détail complet de ce mécanisme central) + un lien "Annuler" cliquable (réutilise `web_import_qt._show_cancel_item`).
- `_detach_worker()` : seul point de sortie d'un worker de `self._worker`, dans cet ordre : marque `_cancelled`, **détache les slots**, puis seulement débloque un éventuel `_ask_ext` en attente (`set_ext_result(None)`) et ferme l'`ExtensionCorrectionDialog` resté ouvert (`self._ext_dialog`, qui ne concernerait plus aucun chargement). Il **garde ensuite une référence dans `_orphan_workers`** (liste module-level) jusqu'au `QThread.finished` natif (non masqué : le signal de fin de `LoadWorker` s'appelle `load_finished`), et seulement alors libère le worker (`dispose_qthread`, `utils.py`) — ou tout de suite si le thread est déjà fini (`isFinished()`). Fin normale (`_on_finished`/`_on_error`/`_on_cancelled`) : `_cleanup_worker()`, lui aussi via `dispose_qthread`. Même famille de piège que `_park_running_worker` (skill `comicvine-metadata-fetch`) : ne jamais détruire un `QThread` encore actif.
- `cancel()` (bouton Annuler du canvas) : `_detach_worker()` + masque le texte rouge + `current_file = None` + `render_mosaic()` + `loading_finished.emit()`.
- `shutdown()` : `_detach_worker()` + masque le texte rouge, **sans toucher à l'état** — appelé à la fermeture du fichier par `PanelWidget._shutdown_loading_on_close` (branché sur `canvas._archive_shutdown_callback`, appelé par `force_close_file`, qui réinitialise lui-même l'état et l'affichage — voir skill `file-close`). Cette même méthode du panneau vide aussi `_pending_load_paths` et annule le chargement d'images isolées en cours.
- `load()` passe aussi par `_detach_worker()` pour l'ancien worker : un nouveau chargement ne détruit jamais un worker encore actif.
- `_on_finished(images_data, errors, first_filepath)` : assigne `images_data`, mémorise `state.disk_signature = file_signature(current_file)` (`utils.py` ; remis à `None` par `load()` au démarrage) — référence comparée avant de réécrire ce fichier, pour détecter une modification faite ailleurs (skill `save-export`), détecte l'état de compression ZIP (`_detect_zip_compression_state`), lit les métadonnées du ComicInfo.xml **du document** (`sync_comic_metadata(st, force=True)` sur l'entrée déjà chargée, jamais une relecture du fichier — règle « un seul ComicInfo.xml, celui de la racine », skill `comicinfo-metadata-editor`), déclenche `render_mosaic()`, `loading_finished.emit()`, puis, s'il reste des erreurs, la fenêtre non bloquante « Fichiers ignorés » (`_MessageDialog`, message callable : lignes reformulées par `read_errors.files_ignored_line`, voir « Raisons d'une page ou d'un fichier illisible »). **Aucune fenêtre pour les pages illisibles** : leur cadre rouge, leur icône et leur info-bulle suffisent (choix de l'utilisateur ; deux fenêtres superposées s'ouvriraient sinon pour une archive contenant les deux sortes d'erreurs).

### `LoadWorker` (QThread)

Fait le vrai travail I/O, jamais d'accès direct aux widgets Qt depuis `run()` (uniquement des `Signal`) :

- **`detect_archive_type(filepath)`** appelé en premier, **avant** de faire confiance à l'extension — un fichier mal nommé (ZIP renommé `.cbr` par erreur) est détecté ici.
- Si le type détecté diffère de l'extension déclarée (`_resolve_filepath`) : `need_ext_dialog` émis, le thread se **bloque** sur un `threading.Event` (`_ask_ext`) jusqu'à ce que `ExtensionCorrectionDialog` (affiché non-modal côté thread UI) rappelle `set_ext_result()` — le thread worker attend, mais **le thread UI n'est jamais bloqué** : l'utilisateur peut continuer à agir sur l'autre panneau pendant ce temps. Trois choix : `rename` (renomme le fichier sur disque vers la bonne extension), `keep` (charge quand même sous le nom déclaré), `None`/annuler (abandonne tout le chargement).
  - `ArchiveLoader._on_need_ext_dialog` capture le worker qui pose la question (`asking_worker`) et lui renvoie la réponse, jamais à `self._worker` : entre l'affichage et la réponse, le worker a pu être détaché (Annuler, fermeture du fichier — qui ferme aussi ce dialogue) ou remplacé par le chargement d'un autre fichier.
  - `_ask_ext` teste `_cancelled` **après** `clear()` de l'événement : un worker détaché pendant qu'il s'apprête à poser la question sort immédiatement, et un détachement postérieur au test débloque forcément son `wait()` — le thread ne reste jamais bloqué indéfiniment.
  - Si `rename` : juste après le `os.rename` réussi, le worker émet `file_renamed(new_filepath)`. `ArchiveLoader._on_file_renamed` met à jour `state.current_file` et rafraîchit immédiatement le titre de fenêtre (`self._win._refresh_title()`, voir skill `window-title`) — sans ça, la barre de titre garderait l'ancien nom (mauvaise extension) jusqu'à la toute fin du chargement, alors que le fichier est déjà renommé sur disque.
- **`load_archive()`** (un seul fichier) vs **`load_multiple_archives()`** (plusieurs fichiers droppés/ouverts ensemble) : la version multi-fichiers fait tout en 2 phases (détection+namelists puis lecture réelle avec une seule barre de progression globale sur le total de pages tous fichiers confondus), et **préfixe `NEW-`** les noms de toutes les archives sauf la première (`add_prefix = archive_idx > 0`) + `entry["source_archive"]` — pour distinguer visuellement/techniquement quelle archive d'origine a fourni quelle page quand plusieurs sont ouvertes d'un coup. Comme `load_archive`, elle teste `self._cancelled` avant chaque archive (phase 1, et après `_resolve_filepath`) et avant chaque page de chaque format (phase 2), et retourne `False` sans émettre de signal : sans ces tests, Annuler ou la fermeture du fichier laisseraient lire toutes les archives jusqu'au bout, fichiers gardés ouverts.
- Chaque format d'archive (ZIP/EPUB, RAR, 7z, TAR) a sa propre branche de lecture dans `_read_entries`/`load_archive`/`load_multiple_archives` — **code dupliqué volontairement entre ces 3 méthodes**, comme documenté pour les flux batch (skill `batch-processing`) : ne pas factoriser sans demande explicite.
- `build_qimage_for_entry(entry)` appelé pour **chaque** entrée juste après `create_entry()` — précalcule le cache vignette (`qt_qimage_large`) en arrière-plan pendant le chargement, avant même que la mosaïque soit rendue (voir skill `mosaic-thumbnails`, section cache pixmap).

## Formats d'archive supportés — détection et lecture

| Format | Détection (magic bytes) | Lecture | Dépendance |
|---|---|---|---|
| CBZ | `PK\x03\x04`/`PK\x05\x06` (ZIP), sans mimetype EPUB | `zipfile` stdlib | aucune |
| EPUB | ZIP + `mimetype` = `application/epub+zip` | `zipfile`, filtré aux seules images (`IMAGE_EXTS`), dans l'ordre de lecture du livre (`epub_reading_order`) | aucune |
| CBR | `Rar!\x1a\x07\x00`/`...\x01\x00` (RAR4/RAR5) | `rarfile` | paquet `rarfile` (+ UnRAR externe) |
| CB7 | `7z\xbc\xaf\x27\x1c` | binaire `7zip/7z.exe` embarqué via `subprocess` (`_list_7z_files`/`_read_7z_file`) | binaire embarqué, pas de lib Python |
| CBT | pas de magic bytes fixes — `tarfile.is_tarfile()` en dernier recours | `tarfile` stdlib (`r:*`, gère nu/gzip/bzip2), **tous** les fichiers (`m.isfile()`, liens ignorés) sous leur chemin complet (`_tar_entry_name`), lus par `_tar_member_reader` | aucune |

**EPUB n'est pas listé comme un "vrai" format cible du projet** (pas d'icône ni de mention dans le nom "CBZ/CBR/CB7/PDF" du CLAUDE.md) mais **est bien supporté en lecture** — traité comme un ZIP filtré aux images. Vérifier ce point avant de supposer qu'EPUB est absent du projet.

**CB7 est le seul format sans bibliothèque Python** : toute la lecture passe par un appel process (`subprocess.run`, `CREATE_NO_WINDOW`) au binaire `7zip/7z.exe` embarqué — voir skill `check-embedded-versions` pour la maintenance de ce binaire. `_to_short_path()` convertit le chemin en 8.3 avant l'appel (contournement d'un problème d'unicode avec l'exécutable 7z sur certains profils Windows). `_list_7z_files` (`7z l -ba -slt -sccUTF-8`) renvoie les **chemins complets** des membres, normalisés en `/` ; `_read_7z_file` (`7z e -so -spd -- <chemin_complet>`, sans `-r`) extrait exactement ce membre vers stdout (`-spd` : un nom contenant `*` ou `?` est lu littéralement, jamais comme un joker). Détail des options et de leurs raisons : skill `batch-cb7-convert`, section "Lecture de l'archive".

**Noms des membres ZIP écrits sans le drapeau UTF-8 — `archive_names.open_zip(fichier)`** : toute archive ZIP dont les noms sont affichés, deviennent des noms de pages ou sont réécrits s'ouvre par `open_zip`, jamais par un `zipfile.ZipFile` direct. Sans le drapeau UTF-8 (bit 11), la norme ZIP impose le cp437 et Python lit ainsi le nom ; or beaucoup d'outils écrivent ces noms en UTF-8 (Mac, Linux, scripts), en cp850 (dossier compressé de Windows en Europe de l'Ouest, dont les majuscules accentuées diffèrent du cp437) ou en cp1252. Lus en cp437, `Été` devenait `├ët├⌐`, `L'Île` `L'╫le` : nom abîmé, ordre des pages faussé, et nom abîmé écrit définitivement au premier enregistrement (avec le drapeau UTF-8 cette fois).
- `zip_member_name(nom)` : UTF-8 valide avec des caractères non ASCII → UTF-8 ; nom cp437 peu plausible (traits de cadre, lettres grecques, symboles : `_looks_misread` ; majuscule accentuée collée après une minuscule : `_mixed_case`) → cp850 s'il est plausible, sinon cp1252 s'il l'est ; sinon inchangé. Mesuré sur 22 noms × 4 codages : tous justes en UTF-8, cp437 et cp850, 19 sur 22 en cp1252. **Limite connue** : un nom cp1252 dont la lettre accentuée commence un mot (`épisode`, `Ça`) est plausible en cp850 et lu ainsi (`Úpisode`) — aucun critère sûr ne départage ces deux codages dans ce cas.
- `fix_zip_names(zf)` corrige sur place `ZipInfo.filename` et `zf.NameToInfo` (lecture par nom) ; **jamais `orig_filename`**, que zipfile compare à l'en-tête local du membre à chaque lecture (sinon `BadZipFile`). Les membres déjà marqués UTF-8 ne sont pas touchés.
- Ouvertures concernées : les cinq de ce chargeur (à garder cohérentes entre elles), `import_merge_qt.py`, la recompression en lot (`batch_dialogs_qt.py`, liste des pages et réécriture), l'import de métadonnées en lot (choix de la couverture et recopie de l'archive, qui doivent voir les mêmes noms), la Bibliothèque (couverture CBZ et EPUB — les chemins de l'OPF sont en UTF-8 —, réécriture de ComicInfo.xml, `virtual_library_panel.py`). Ouvertures laissées en `zipfile.ZipFile` : celles qui ne regardent que le nombre de membres, le commentaire d'archive ou la présence de ComicInfo.xml. **Piège** : un test qui exécute une fonction extraite par AST doit avoir `open_zip` dans son espace de noms (`tests/test_batch_metadata_save.py`).
Testé par `tests/test_image_names_and_order.py` (ZIP de synthèse dont les noms sont écrits sans drapeau, dans chacun des quatre codages).

**Lecture des membres — un lecteur par format, toujours le même** (`archive_loader.py`, utilisés par les branches du chargeur, `import_merge_qt.py` et les lots CBR/CBT) :
- **ZIP (CBZ/EPUB) — `_zip_member_reader(archive)`**, jamais `archive.read(nom)` : un ZIP peut contenir deux membres de même nom, et `read(nom)` renvoie le contenu du **dernier** pour chacun ; le premier serait affiché avec les données du second, puis définitivement perdu au prochain enregistrement. `_zip_member_reader` rend chaque homonyme à son tour (appelé une fois par nom de `namelist()`, dans l'ordre — le tri naturel est stable). Ailleurs (recompression, réécriture du ComicInfo de la Bibliothèque, import de métadonnées en lot), lire par `ZipInfo` (`zf.read(info)` sur `infolist()`).
- **TAR (CBT) — `_tar_member_reader(archive)`**, jamais `archive.getmember(nom)` : `getmember` rend le **dernier** membre de ce nom (deux pages homonymes afficheraient la même image), y compris un lien symbolique homonyme placé après la page. Le lecteur ne retient que les fichiers ordinaires et rend chaque homonyme à son tour, comme pour le ZIP. `_tar_info_read(archive, member)` lit un `TarInfo` déjà choisi (lot CBT, qui itère sur les membres).
- **RAR (CBR) — `_rar_read(archive, nom)`**.
- **7z (CB7) — `_read_7z_file`** (voir plus haut).
- **Taille maximale d'un membre — `MAX_MEMBER_SIZE`** (500 Mo, la limite d'une image ouverte seule) : `_check_member_size` contrôle la taille **annoncée** par l'archive avant toute lecture, dans les trois premiers lecteurs ; pour le CB7, `_read_7z_file` contrôle la taille **reçue** (voir ci-dessous). Une page de quelques Ko qui se décompresse en plusieurs Go (bombe de décompression), ou un membre TAR « creux » de taille annoncée énorme, épuiseraient sinon la mémoire. Le membre trop grand lève `ValueError` (« 4.20 Go > 500.0 Mo », sans mots : devient la raison affichée de la page illisible) ; il devient une page illisible que l'enregistrement refuse d'omettre, et un lot déclare son CBZ incomplet (source gardée). **CB7** : `_read_7z_file` lit la sortie de 7z par blocs de 1 Mo (`subprocess.Popen`) et arrête l'extraction (`proc.kill()`) dès que le total dépasse la limite — une limite sur ce qui est reçu, qui protège tous les appelants sans changer leur code ; la sortie d'erreur est lue par un thread (un tube plein bloquerait 7z, donc la lecture de la sortie). `zipfile` ne rend jamais plus que la taille annoncée : pour lui, la contrôler suffit. Testé par `tests/test_7z_member_extraction.py` (`test_member_larger_than_the_limit_is_refused`, limite abaissée le temps du test).
Testé par `tests/test_archive_member_reading.py` (fonctions et constante extraites par AST : un nouveau lecteur appelé par l'un d'eux doit être ajouté à `_FUNCS`).

**CBT — tous les fichiers, chemin complet** : `_get_namelist` garde tous les fichiers d'un TAR (ComicInfo.xml, `.nfo`, `.txt`, comme CBZ/CBR/CB7), et `_tar_entry_name(member_name)` en fait le nom de la page (chemin complet sans `./` ni `/` initial, `\` → `/`). La fonction vit dans **`modules/qt/archive_names.py`** (`tar_entry_name`, module sans Qt, importée ici sous le nom `_tar_entry_name`) : la conversion en lot des CBT l'applique aussi, sans charger ce module. L'import de métadonnées en lot applique `contained_member_name` (même module), qui retire en plus `..`, lettre de lecteur et chemin réseau (skill `batch-metadata-import`). Sans elle, le nom brut `./p01.jpg` donnerait au CBZ produit un faux sous-dossier « . » ; toute règle de nommage commune à plusieurs lecteurs d'archives se place dans `archive_names.py`. Jamais le seul nom de base : deux pages homonymes de dossiers différents porteraient le même nom, et une conversion en CBZ (qui propose ensuite de supprimer le CBT) perdrait la structure et les fichiers non-image. Même règle dans `import_merge_qt.py`. EPUB reste filtré aux images et aplati (choix assumé : seules ses images sont reprises).

**Formats d'image reconnus — `archive_names.restrict_pillow_formats()`**, appelée une fois au démarrage dans `MosaicView.py` (juste après `Image.MAX_IMAGE_PIXELS`) : `Image.ID` réduit **sur place** (Image.open la compare par identité) aux formats de `_FORMAT_EXTENSIONS` (AVIF, BMP, DIB, GIF, PNG, ICO, JPEG, TIFF, WebP ; MPO passe par le décodeur JPEG). `Image.open` choisit le décodeur d'après le contenu, pas l'extension : sans cette restriction, une page `.jpg` contenant un EPS serait rendue par Ghostscript s'il est installé (programme externe aux failles connues), et les décodeurs de formats rares élargiraient la surface d'attaque des fichiers téléchargés. Une telle page devient illisible. L'enregistrement n'est pas concerné. `ImageGrab.grabclipboard` (presse-papiers) construit ses images sans passer par ce registre. Le processus PDF (`spawn`) réexécute le haut de `MosaicView.py` et reçoit la même restriction. **Ajouter un format d'image géré** : l'ajouter à `_FORMAT_EXTENSIONS` (et à `IMAGE_EXTS`) ; sinon Pillow ne le reconnaîtra pas. Testé par `tests/test_pillow_formats.py` (registre restauré après chaque test).

**EPUB — ordre de lecture et rang dans le nom** (`archive_names.py`, appliqué par les trois branches ZIP du chargeur et par `import_merge_qt.py`, donc aussi par la conversion CBZ de la Bibliothèque) :
- `epub_reading_order(zf, image_names)` range les images dans l'ordre du livre : documents de la « spine » de l'OPF (chemin donné par `META-INF/container.xml`), puis images de chaque document dans leur ordre d'apparition (`<img src>`, `<image xlink:href>`) ; les images qu'aucun document n'affiche suivent par nom, l'image de couverture déclarée dans l'OPF (`properties="cover-image"`) passant en tête. Ordre des noms seul si l'EPUB est incomplet ou illisible. Le tri par nom ne suit pas le livre : les images d'un EPUB portent des noms arbitraires (`cover.jpg`, `image_12.png`). **Analyse par expressions régulières, jamais par un parseur XML** : aucune entité externe d'un EPUB téléchargé n'est résolue. Membres lus par leur `ZipInfo`.
- `epub_page_name(position, member_name)` nomme la page `0001_<nom de base>` (rang à partir de 1) : sans ce rang, l'ordre de lecture serait perdu dès que les pages sont triées par nom (ouverture de plusieurs archives, ajout à un comic, tout lecteur du CBZ enregistré). `without_epub_rank(nom)` retire ce rang (et un préfixe `NEW-`) pour retrouver le nom de base (rattachement des erreurs de lecture, `_attach_read_errors`).
Testé par `tests/test_image_names_and_order.py` et `tests/test_archive_member_reading.py`.

**TIFF de plusieurs pages dans une archive — une page du comic par page (DÉCISION DÉFINITIVE, aussi dans `CLAUDE.md`)** : un TIFF multipage n'a pas sa place dans un comic. Un CBZ est une suite d'images, une par page ; les lecteurs de BD n'en montrent que la première, et dans la mosaïque une seule vignette cachait les autres pages, qu'on ne pouvait ni voir, ni copier, ni déplacer, ni supprimer une à une. Donc, à la fin de toute lecture d'archive — `LoadWorker.run` (ouverture d'un ou plusieurs fichiers, et conversion CBZ de la Bibliothèque qui passe par ce worker) et `ImportMergeWorker.run` (ajout d'une archive à un comic ouvert) —, `_expand_multipage_tiffs_with_thumbnails(entries)` (`archive_loader.py`) appelle `entries.expand_multipage_tiffs(entries, IMAGE_EXTS)` puis construit le cache vignette des pages créées :
- chaque TIFF `is_multipage_tiff` est remplacé, **à sa place dans la liste**, par une entrée par page : `Ch1/02.tif` → `Ch1/02_page_0001.tif`, `Ch1/02_page_0002.tif`… (même dossier, même préfixe `NEW-`/de fusion, même `source_archive`) ;
- chaque page **reste un TIFF** d'une seule page (`split_multipage_tiff_pages` : compression, DPI et profil ICC d'origine, mode de couleur inchangé — jamais de conversion en JPEG, contrairement à `create_entries_from_tiff` pour un TIFF ouvert seul) ;
- le comic n'est pas marqué modifié par ce découpage : rien n'est écrit tant que l'utilisateur n'enregistre pas ; tout enregistrement écrit ensuite une image par page ;
- un TIFF qui ne peut pas être découpé reste en une seule entrée (aucune perte : les opérations le traitent page par page, `image_ops.has_several_frames`, skill `apply-image-operation`).
Ne jamais revenir à une seule vignette par TIFF multipage. Les lots de conversion (skill `batch-processing`) et l'import de métadonnées en lot ne passent pas par ce chargeur : ils recopient le TIFF tel quel. Testé par `tests/test_tiff_pages.py` (`test_every_tiff_page_becomes_a_page_in_place`, `test_split_keeps_format_mode_compression_and_dpi`).

## `create_entry()` — le point de passage obligé (`entries.py`)

Toute donnée binaire qui devient une entrée de `images_data`, quelle que soit sa provenance (archive, fichier isolé, TIFF multi-page, collage/merge), passe par cette fonction :

1. Détermine `is_image` (extension dans `image_exts`) et `is_dir` (`file.endswith("/")`).
2. Si image : décodage PIL en 2 passes (`img.verify()` puis réouverture + `img.load()`, nécessaire car `verify()` invalide l'objet pour un usage ultérieur) — capture `DecompressionBombError` séparément (image bombe, au-delà d'un milliard de pixels : marque `is_too_large=True`, `is_corrupted=True`, garde les dimensions lues dans l'en-tête par `_header_size`, sans jamais lever la limite de pixels) d'une corruption normale (`is_corrupted=True`, `is_too_large=False`, `corruption_reason=str(e)`). Voir skill `corrupted-images` pour le signalement visuel, le tooltip dédié et le mécanisme de remplacement, ainsi que le second point de détection tardif dans `ensure_image_loaded()`. **Image sans données** (`data is None` : membre illisible dans l'archive — CRC faux, compression non prise en charge comme Deflate64, membre chiffré) : marquée `is_corrupted=True`. À la fin du chargement, `ArchiveLoader._on_finished` appelle `_attach_read_errors(images_data, errors)` : chaque erreur « nom: message » du worker devient le `corruption_reason` de la page correspondante (message technique brut, ex. « Bad CRC-32 for file '03.jpg' », traduit seulement à l'affichage dans l'info-bulle, voir ci-dessous) et sort de la liste « Fichiers ignorés » : une page illisible n'est signalée que par son cadre rouge. Restent dans « Fichiers ignorés » les fichiers non-image illisibles et les erreurs d'archive. Correspondance des noms : chemin du membre tel quel, avec préfixe `NEW-`, nom de base précédé du rang de lecture (EPUB, retrouvé par `without_epub_rank`) ou `_tar_entry_name` ; homonymes servis dans l'ordre. Testé par `tests/test_archive_member_reading.py`. Sans erreur rattachée, `corruption_reason` reste `None` (info-bulle `tooltip.unknown_error`). Elle reste dans `images_data` : ses données n'existent que dans le fichier d'origine, et les écritures refusent de l'omettre (`MissingPageDataError`, skill `save-export`).
2b. **Extension d'après le vrai format** : `name_for_real_format(nom, img.format)` (`archive_names.py`) — une page dont l'extension annonce un autre format que le sien (PNG nommé `.jpg`, WebP nommé `.png`) prend l'extension de son vrai format (`orig_name`, `extension`), et `entry["extension_corrected_from"]` garde l'ancienne extension (`.jpg`), affichée dans l'info-bulle (`tooltip.extension_corrected`, `tooltips_qt.get_tooltip_text`). Sans cela, la page serait réenregistrée dans le format de son extension à la première retouche (un PNG transparent devenait un JPEG) ; les lecteurs se fient aussi à l'extension. Seuls les formats d'image gérés sont concernés (`_FORMAT_EXTENSIONS` : JPEG et MPO, PNG, WebP, GIF, BMP, TIFF, AVIF, ICO) ; une extension synonyme (`.jpeg`, `.jfif`, `.tiff`) est gardée. `_install_loaded_pages` marque alors le comic modifié, pour que l'enregistrement écrive le bon nom. Les lots CBR/CB7/CBT et images → CBZ appliquent la même règle (skill `batch-processing`). `same_image_format(ext_a, ext_b)` dit si deux extensions désignent le même format (export d'une page, skill `save-export`). Testé par `tests/test_image_names_and_order.py`.
3. Stocke `img_width`/`img_height`/`dpi` immédiatement (évite de rouvrir l'image plus tard, ex. pour la renumérotation — voir skill `renumbering`, `page_detection.py` qui lit ces mêmes clés).
4. **GIF animé** : détecté avant de garder l'image en mémoire (`n_frames > 1`), stocke uniquement les métadonnées légères (durées par frame, loop, disposal) — **pas** toutes les frames décodées (lazy loading, voir `get_gif_frame()` pour le chargement à la demande d'une frame). Voir skill `animated-gif` pour la création/édition d'un GIF animé (consomme ces mêmes métadonnées) et skill `viewers` pour la lecture animée dans la visionneuse principale.
   **WebP/PNG/AVIF animés** : pour toute image non-GIF, `set_animated_image_info(entry, img)` (`entries.py`) détecte plusieurs frames sur les extensions de `_ANIMATABLE_EXTS` et pose `is_animated_image=True` + `gif_frame_count`/`gif_durations` (mêmes clés que les GIF animés). Les durées WebP/AVIF ne sont renseignées qu'après décodage de chaque frame (`im.load()` dans la boucle) et sont converties en `int` (le PNG animé renvoie des flottants, refusés par le minuteur Qt de la lecture). **Ce drapeau a les mêmes effets que `is_animated_gif`** (les deux testés ensemble par `image_ops.is_animated_entry`) : lecture animée et grisage des outils (skill `viewers`), traitement frame par frame de la rotation, du miroir, du redimensionnement, du redressement automatique et de la scission (`transform_animated_entry`, skill `rotate-flip`), conversion vers un format animable (skill `image-format-conversion`), jointure (skill `page-merge`) et nombre de frames dans l'info-bulle de la mosaïque (`get_tooltip_text`, `tooltips_qt.py`). Seule la fenêtre des GIF animés (skill `animated-gif`) reste réservée aux GIF. Il est remis à `False` par `save_image_to_bytes` (qui n'écrit qu'une image) et recalculé après un undo/redo (`_reload_thumb_qt`, skill `undo-redo`). **TIFF de plusieurs pages** : la même fonction pose `is_multipage_tiff` (`.tif`/`.tiff` avec `n_frames > 1`), remis à `False` dans les mêmes cas ; il ne fait pas de la page une image animée, mais les opérations qui réécrivent l'image le traitent page par page (`image_ops.has_several_frames`, skill `apply-image-operation`).
5. **`entry["img"]` reste `None` après `create_entry`** (lazy loading systématique) — `ensure_image_loaded(entry)` le décode à la demande plus tard, `free_image_memory(entry)` le libère après usage tout en gardant `entry["bytes"]`. Ne jamais supposer que `entry["img"]` est peuplé juste après un chargement.
6. Calcule `entry["_hash"]` (MD5) si image non corrompue — voir skill `duplicate-detection`, ce hash est le même que celui consommé par `recompute_duplicate_groups`.

**`create_entry_from_file(filepath, image_exts)`** — variante pour un fichier **sur disque** (pas depuis une archive ouverte) : limite 500 Mo (`FileTooLargeError`), lit tous les bytes puis délègue à `create_entry`. Utilisée par `_ImageLoadWorker` pour les images isolées.

**`create_entries_from_tiff(filepath, image_exts, add_prefix=False, failures=None)`** — fichier TIFF ouvert seul (hors archive). Même règle que pour un TIFF contenu dans une archive (voir plus haut, `split_multipage_tiff_pages`) : **chaque page reste un TIFF**, dans son mode d'origine (palette, 1 bit, 16 bits, CMJN, alpha), avec sa compression, son DPI et son profil ICC (`_single_page_tiff_bytes`), jamais de conversion en JPEG ni de changement d'extension.
- Un TIFF d'une seule page (ou que PIL n'ouvre pas) : une entrée avec les **bytes d'origine** et le nom du fichier, comme `create_entry_from_file` (une image illisible y est marquée corrompue).
- Un TIFF de plusieurs pages : une entrée par page, `<nom>_page_0001<ext>`… (même extension que le fichier), préfixe `NEW-` si `add_prefix`. Lecture page par page par PIL (`seek`) : une page illisible n'arrête pas la lecture des suivantes.
- **Repli `_tifffile_page_bytes`** pour une page que PIL ne sait pas décoder (compression absente de sa libtiff) : la page lue par `tifffile`, réécrite en TIFF sans perte, **seulement** pour les données sans ambiguïté (niveaux de gris 8/16 bits, RGB/RGBA 8 bits). **Piège** : `tifffile.asarray()` rend les index d'une image à palette (sans la palette), les quatre canaux d'un CMJN (que `Image.fromarray` prend pour du RGBA) et des valeurs 16 bits que `convert('RGB')` écrête en blanc — toute autre donnée est signalée comme page illisible plutôt que convertie en fausses couleurs.
- Les sous-images internes (SubIFD : vignettes, pyramides) ne sont pas des pages et ne sont pas lues.
- **Page illisible** : ajoutée à `failures` sous la forme `(page, message)` (page à partir de 1), jamais ignorée en silence.
Testé par `tests/test_tiff_pages.py`.

**Orientation EXIF** : `create_entry` mémorise les dimensions dans le sens d'affichage (`oriented_size`) ; `ensure_image_loaded` rend l'image tournée selon sa balise d'orientation (`oriented`). Fonctions de décodage d'une page et pièges : skill `apply-image-operation`, « Décoder la page ».

**`image_dpi(img)`** (`entries.py`) — résolution `(x, y)` d'une image PIL, `None` si elle n'en a pas. **Toujours l'utiliser à la place de `img.info.get("dpi")`** : Pillow annonce `(1, 1)` pour un TIFF sans balise de résolution, et cette valeur suit l'image dans ses copies et transformations (`img.info`) — prise pour une vraie résolution, elle serait affichée (« DPI : 1 ») et écrite dans les fichiers produits. Une résolution d'1 dpi ou moins vaut absence de résolution. Utilisée par `create_entry`, `get_image_metadata`, `save_image_to_bytes`, `split_multipage_tiff_pages`, `create_entries_from_tiff`, `image_ops` (conversion, TIFF de plusieurs pages), la jointure et la normalisation des pages des lots.

## Chargement d'images isolées — `_ImageLoadWorker` / `_start_image_load` (`panel_widget.py`)

Distinct du chargement d'archive : pas de réinitialisation systématique de `images_data`, peut s'ajouter à une session déjà ouverte.

- `_ImageLoadWorker.run()` : pour chaque fichier, si `.tiff`/`.tif` → `create_entries_from_tiff` (peut produire plusieurs entrées) ; sinon → `create_entry_from_file` (une entrée). Toutes reçoivent `entry["source_archive"] = "loose"` (pas de fichier archive d'origine) et, si `already_open`, un préfixe `NEW-` sur le nom (même convention que les archives fusionnées après la première) — **sauf** si le worker a été construit avec `existing_names` (set de noms déjà présents, passé uniquement par le coller Ctrl+V, voir skill `clipboard`) : dans ce cas, une vraie collision de nom avec `existing_names` est résolue par un suffixe `-COPY`/`-COPYn` au lieu du préfixe `NEW-`, et une absence de collision ne change pas le nom du tout (pas de préfixe ajouté). `_start_image_load()` accepte ce même paramètre `existing_names` et le transmet tel quel au worker ; `PanelWidget._load_files()` ne le calcule que si appelé avec `rename_collisions_as_copy=True`.
- `_start_image_load()` (câblage UI, `PanelWidget._start_image_load`) : annule un éventuel worker précédent encore actif avant d'en lancer un nouveau (pas de `_park_running_worker` ici — l'ancien worker reste référencé par ses propres closures jusqu'à sa fin, puis se libère via `dispose_qthread` dans le slot de son signal de fin). Même pattern d'overlay canvas + bouton Annuler que `ArchiveLoader`.
- `on_finished`/`on_cancelled` ne font rien si `self._image_worker` n'est plus ce worker-là : annulé (Annuler pendant le dernier fichier — `finished` est alors émis au lieu de `cancelled`), remplacé par un chargement plus récent (dont ils écraseraient sinon l'overlay et la référence), ou arrêté à la fermeture du fichier. `on_finished` ignore aussi le résultat si `state.doc_generation` a changé depuis le lancement, après avoir masqué son texte de progression et libéré `_image_worker`.
- **Ouverture d'une archive ou d'un PDF pendant un chargement d'images** (panneau vide : images déposées, puis Ctrl+O sur un CBZ avant la fin) : le chargement d'images n'est pas un « chargement remplaçant » (`_replacing_load_in_progress`), et ses images ne sont pas encore dans `images_data`, donc le panneau passe pour vide et l'archive est ouverte. `_load_files` lance alors l'archive ou le PDF par `_start_replacing_load(start)` : `_stop_image_load()` arrête le chargement d'images (texte masqué, jeton `_IMAGE_LOAD_HINT` libéré) et rend ses fichiers, remis en attente avec la génération du nouveau document (`_pending_load_paths`) ; ils sont ajoutés au comic une fois chargé (`_run_pending_loads`), ou ouverts si le chargement échoue. **Piège** : sans cet arrêt, le chargement d'images finit sur une génération changée : son résultat est abandonné, et les images déposées sont perdues sans message. `_shutdown_loading_on_close` passe aussi par `_stop_image_load`.
- À la fin (`on_finished`) : les nouvelles entrées sont ajoutées à `images_data`, retriées par tri naturel (`_natural_sort_key`), `save_state_data` (point undo, voir skill `apply-image-operation` pour le pattern général) — puis `render_mosaic()`.
- **Fichiers ou pages non chargés** : le worker les accumule dans `self.errors` — `('too_large', nom, taille)` (au-delà de 500 Mo), `('unreadable', nom, message)` (exception, fichier disparu ou inaccessible — `create_entry_from_file` renvoie alors `None`, `create_entries_from_tiff` une liste vide) et `('tiff_page', nom, page, message)` (page illisible d'un TIFF de plusieurs pages, `failures` de `create_entries_from_tiff`). `on_finished` les affiche (20 au plus) dans la fenêtre « Fichiers ignorés » (`archive_loader._MessageDialog`, titre `messages.warnings.files_ignored.title`), avec un message callable recalculé à chaque changement de langue ; chaque ligne est produite par `_image_load_error_text` (`panel_widget.py`, clés `messages.errors.file_too_large.message`, `messages.warnings.files_ignored.unreadable` / `.tiff_page`, message technique brut entre parenthèses). **Piège** : ne jamais ignorer un fichier ou une page en échec (`except: pass`, `continue`) — le document produit ensuite aurait des pages en moins sans que personne le sache (garde : `tests/test_check_no_swallowed_loop_errors.py`).
- **`st.first_image_dir`** n'est renseigné que si le panneau était vide avant l'ajout (`not st.images_data` au moment du calcul) — sert à mémoriser le dossier d'origine pour un futur enregistrement en CBZ sans archive source.

## Fusion d'une archive existante — `import_merge_qt.py`

Distinct de `ArchiveLoader.load()` : ajoute le contenu d'une **deuxième** archive à la suite du comic déjà affiché, sans toucher aux pages existantes.

- `import_and_merge_archive(filepath, parent, canvas, state)` calcule un `merge_prefix` unique (`state.merge_counter`, incrémenté à chaque fusion) et lance `ImportMergeWorker`.
- Chaque entrée importée est préfixée par ce `merge_prefix` sur **le nom de fichier ET le chemin de sous-dossier** (`_add_prefix`, gère le cas `path/file.ext` en préfixant les deux segments séparément) — pas seulement `NEW-` comme pour les images isolées ou les archives multiples au premier chargement. **Sauf le `ComicInfo.xml` de la racine de l'archive** (`is_comic_info_name`), gardé tel quel puis nommé à l'ajout par `name_incoming_comic_infos` (`_append_merged`) : il devient les métadonnées du comic s'il n'en a pas, sinon `ComicInfo_0002.xml`… (skill `comicinfo-metadata-editor`). **Piège** : préfixé (`NEW01-ComicInfo.xml`), il ne serait plus jamais le ComicInfo.xml du comic, même pour un comic qui n'en a pas.
- Réutilise directement `create_entry`, les lecteurs de membres (`_zip_member_reader`, `_tar_member_reader`, `_rar_read`, `_list_7z_files`/`_read_7z_file`), `ExtensionCorrectionDialog` du loader — mêmes formats supportés, même détection de type, même dialogue de correction d'extension. **Membre illisible** : comme à l'ouverture, il n'arrête jamais l'ajout. `ImportMergeWorker.run` lit chaque membre par `_read(reader, file)` (erreur rendue au lieu d'être levée) puis `_note_read_error` : une page illisible reçoit sa raison (`corruption_reason`), tout autre fichier illisible va dans la liste d'erreurs, transportée par le signal `finished(new_entries, errors)` et affichée dans « Fichiers ignorés » (`files_ignored_line`). **Piège** : une erreur CRC d'un membre ZIP lève `zipfile.BadZipFile` (et `BadRarFile` pour un CBR) ; laissée remonter, elle passerait pour une archive d'un autre format et ferait proposer de **renommer l'archive** de l'utilisateur. `bad_zip_file`/`bad_rar_file` ne doivent venir que de l'ouverture de l'archive entière.
- `on_finished` ignore le résultat si `state.doc_generation` a changé depuis le lancement (document fermé ou remplacé pendant la fusion) ; le worker est libéré par `dispose_qthread` dans le slot de son signal de fin.
- **Fermeture du fichier pendant la fusion** : `_start_worker` inscrit `_cancel` par `register_cancel_on_close(canvas, _cancel)` et `_cleanup` le retire ; `force_close_file` l'appelle donc comme le bouton Annuler (skill `file-close`, « Arrêt des opérations à la fermeture »). L'inscription se fait dans `_start_worker`, pas en tête de `import_and_merge_archive` : après une correction d'extension, un second worker est lancé par ce même `_start_worker`.
- Après fusion, la **renumérotation automatique** se déclenche selon `state.renumber_mode` (voir skill `renumbering`) — le préfixe `merge_prefix` garantit que les pages fusionnées ne collisionnent pas avec les noms existants avant que la renumérotation, si activée, ne les renomme proprement.

## Comment ça entre dans la mosaïque et les panneaux

Aucun de ces mécanismes ne connaît directement `MosaicCanvas` au-delà de l'appel final `render_mosaic()` — le contrat est entièrement au niveau de `state.images_data` (liste de dicts d'entrées) :

1. Un loader (quel qu'il soit) peuple/complète `state.images_data`.
2. Il appelle `self._canvas.render_mosaic()` (voir skill `mosaic-thumbnails`) qui reconstruit la scène depuis `images_data` — c'est le seul point de contact avec le rendu visuel.
3. Chaque `PanelWidget` (panel1/panel2 en split-view, voir skill `panels`) a sa **propre** instance d'`ArchiveLoader`/`_pdf_loader`, construite avec son propre `self._state` et son propre `self._canvas` — deux panneaux ne partagent jamais un chargement, un drop sur le panneau 2 ne touche jamais `images_data` du panneau 1.
4. La **Bibliothèque** (voir skill `library`) n'utilise **aucun** de ces workers pour son scan (elle lit directement le ComicInfo.xml de la racine de l'archive — `library_db`, `read_comic_info` pour son panneau virtuel — et `parse_comic_info_xml`, sans construire d'`images_data`) mais délègue à `PanelWidget._load_files()` (donc à ce mécanisme) au moment où l'utilisateur choisit d'ouvrir un comic indexé dans un panneau réel.

## Comment étendre

- **Ajouter un nouveau format d'archive lisible** : (a) ajouter la détection magic bytes dans `archive_type_detector.py` (`detect_archive_type`), (b) ajouter l'extension à `_EXT_TO_TYPE`/`_TYPE_TO_EXT`/`_ERROR_KEYS` dans `archive_loader.py`, (c) ajouter une branche de lecture dans `_get_namelist`/`_read_entries`/`load_archive`/`load_multiple_archives` (4 endroits, suivre le pattern CBT — le plus simple, aucune dépendance externe), (d) ajouter l'extension à la liste `cbz_files` dans `PanelWidget._load_files()`, (e) si la fusion doit aussi le supporter, ajouter la branche correspondante dans `import_merge_qt.py`.
- **Changer la limite de taille de fichier image isolée** (500 Mo) : `FileTooLargeError`/constante `max_size` dans `entries.py`, dupliquée dans `create_entry_from_file` et `create_entries_from_tiff` — mettre à jour les deux, et `MAX_MEMBER_SIZE` (`archive_loader.py`) pour les membres d'archive.
- **Changer le comportement de correction d'extension** : `ExtensionCorrectionDialog` (`archive_loader.py`) est réutilisée telle quelle par `import_merge_qt.py` — toute modification de ses 3 choix (`rename`/`keep`/annuler) impacte les deux chemins.
- Respecter les 8 règles UI Qt obligatoires du CLAUDE.md pour les dialogues de ce module (`ExtensionCorrectionDialog`, `_MessageDialog` — déjà non-modaux, `_wt()` pour les titres déjà en place). `_MessageDialog(parent, title_key, msg)` accepte pour `msg` un texte ou un callable `() -> str`, rappelé par `_retranslate()` : passer un callable dès que le message contient un texte traduit (cas de `_warn_pdf_pages_ignored`, skill `pdf-loading`).

## Pièges connus

- **`ArchiveLoader.load()` réinitialise toujours `state`** — ne jamais l'utiliser pour un besoin de fusion ; c'est `import_merge_qt.py` qu'il faut appeler dans ce cas. `PanelWidget._load_files()` fait déjà cette distinction via `already_open`, ne pas la contourner dans un nouveau call-site.
- **Le thread `LoadWorker` peut se bloquer volontairement** sur `_ask_ext` en attendant une réponse UI — ce n'est pas un bug de threading, c'est le mécanisme voulu pour le dialogue de correction d'extension. Ne jamais court-circuiter ce blocage sans comprendre que le thread UI, lui, reste réactif.
- **Tout retrait d'un worker encore potentiellement actif passe par `_detach_worker()`** — jamais `deleteLater()` ni réassignation directe de `self._worker` : un `QThread` détruit pendant qu'il tourne fait planter l'application (« QThread: Destroyed while thread is still running ») ou corrompt la mémoire de façon différée.
- **Dans `_detach_worker`, débrancher les slots AVANT de débloquer le worker** : débloqué d'abord (`set_ext_result`), le worker a le temps d'émettre `cancelled` vers ce chargeur, dont le slot `_on_cancelled` s'exécute alors après coup et remet `current_file` à `None` — sur le document suivant si un autre fichier est chargé entre-temps.
- **Débrancher ne suffit pas : chaque slot vérifie son émetteur** (`ArchiveLoader._from_current_worker`, `self.sender() is self._worker`, en tête de `_on_progress`, `_on_finished`, `_on_error`, `_on_cancelled`, `_on_file_renamed`, `_on_need_ext_dialog`). Un signal émis juste avant le détachement est déjà en file d'attente, et Qt le livre quand même (la connexion n'est vérifiée qu'à l'émission) : sans ce contrôle, un chargement annulé au dernier moment installe ses pages, éventuellement dans le document suivant. Même règle pour la fusion d'archive (`import_and_merge_archive`) : `_cancel` pose `cancelled_flag`, que `on_finished`, `on_error`, `on_bad_zip`/`on_bad_rar` testent en premier (`_cleanup`, connecté avant eux, remet déjà `_worker_ref[0]` à `None` : la référence ne peut pas servir de test).
- **`_on_need_ext_dialog` renvoie la réponse au worker qui a posé la question** (`asking_worker`, capturé à l'affichage), jamais à `self._worker` : il a pu être détaché ou remplacé entre-temps.
- **Fermer le fichier doit arrêter le chargement en cours** : sans l'appel à `shutdown()` depuis `force_close_file`, le worker continue, son `_on_finished` recharge le fichier qu'on vient de fermer, et le chargement suivant dans ce panneau trouve un worker encore actif. Tout nouveau chargeur asynchrone propre à un panneau doit être arrêté de la même façon à la fermeture du fichier.
- **Fin d'un chargement d'archive ou de PDF — `_install_loaded_pages(state, pages)`** (`archive_loader.py`, appelée par `ArchiveLoader._on_finished` et `PdfLoader._on_finished`, testée par `tests/test_loaded_pages_install.py`) : les pages lues deviennent le document, **suivies** de celles ajoutées pendant le chargement (import web, numérisation, collage d'une image), qui marquent alors le document modifié (comme une page dont l'extension a été corrigée, `extension_corrected_from`) ; un seul ComicInfo.xml y garde ce nom, les autres (homonymes de l'archive, fichier déposé pendant le chargement) deviennent `ComicInfo_0002.xml`… (`name_incoming_comic_infos`, skill `comicinfo-metadata-editor`) ; puis `reset_history`. **Pièges** : remplacer simplement `images_data` effacerait ces ajouts sans avertissement ; et garder l'historique laisserait un état pris pendant le chargement, qu'un Annuler juste après l'ouverture restaurerait à la place du fichier ouvert (un « Appliquer » écraserait ensuite le CBZ avec ces seules pages). Les fichiers reçus pendant ce temps sont, eux, mis en attente par `_load_files` (étape 0 du routeur) et fusionnés à la fin ; le dépôt de pages depuis l'autre panneau est refusé (`_on_inter_panel_drop`, skill `drag-and-drop`). Ne pas contourner ces règles dans un nouveau point d'entrée qui ajouterait des pages au panneau.
- **Ajouts dans un document ouvert (fusion d'archive `import_merge_qt.on_finished`, ajout d'images `PanelWidget._start_image_load`)** : appliqués par `state.run_when_idle` (à la fin d'une opération en cours sur le document, skill `undo-redo`), encadrés d'un `save_state` avant et après (point d'annulation propre à l'ajout).
- **`entry["img"]` est `None` après `create_entry`/tout chargement** — toujours passer par `ensure_image_loaded()` avant de lire une image PIL complète depuis une entrée fraîchement chargée, ne jamais supposer qu'elle est déjà décodée.
- **Le préfixe de nommage diffère selon le chemin** : `NEW-` (images isolées ajoutées à une session ouverte, ou archives 2..N d'un chargement multi-fichiers) vs `merge_prefix` unique incrémental (fusion explicite d'une archive via `import_merge_qt.py`) vs suffixe `-COPY`/`-COPYn` (uniquement le coller Ctrl+V d'une page, en cas de collision réelle avec un nom déjà présent — voir skill `clipboard`) — ne pas mélanger ces conventions en copiant un pattern de l'une vers l'autre sans vérifier laquelle s'applique.
- **CB7 dépend d'un binaire externe, pas d'une lib Python** — un changement de version de `7zip/7z.exe` peut changer le format de sortie de `7z l -ba -slt -sccUTF-8` parsé par `_list_7z_files`, à revérifier après une mise à jour du binaire (voir skill `check-embedded-versions`) ; `tests/test_7z_member_extraction.py` exécute les vraies fonctions sur une vraie archive et détecte ce type de rupture.
- **Un membre CB7 est un fichier dès que ses attributs Windows ne contiennent pas `D`** (`_is_7z_file_block`) — jamais une égalité avec `Attributes = A` : un fichier en lecture seule (`RA`), caché (`HA`), sans bit archive (`N`) ou venant d'Unix (`A_ -rw-r--r--`) serait ignoré sans erreur, et une conversion (lot CB7, import de métadonnées, Bibliothèque, « Appliquer et créer un CBZ ») supprimerait ensuite le CB7 sans ces pages. Testé par `tests/test_7z_member_extraction.py` (`test_list_keeps_read_only_hidden_and_non_archive_files`).
- **`_read_7z_file` attend le chemin complet du membre, jamais un nom seul** — avec un nom seul, deux pages homonymes dans des dossiers différents (`A/page01.jpg`, `B/page01.jpg`) afficheraient la même image sans aucune erreur (7z concatène les deux avec `-r`, PIL décode la première ; sans `-r`, un nom seul ne trouve que le fichier à la racine). Tous les appelants (loader, `import_merge_qt.py`, conversion en lot CB7, import de métadonnées en lot, couverture de la Bibliothèque) passent un nom issu de `_list_7z_files` : garder ce contrat pour tout nouvel appelant. **Ne jamais retirer `-spd`** : sans elle, un nom contenant `*` ou `?` est un joker, 7z rend les contenus de tous les membres qu'il désigne mis bout à bout, la page affiche l'image d'un autre membre, et le lot CB7 l'écrit ainsi dans le CBZ avant de supprimer le CB7 (la relecture du CBZ contrôle sa structure, pas son contenu). Testé par `test_wildcard_characters_in_member_name_are_literal`.
- **Dans `_on_finished`, toujours utiliser `self._state`, jamais le singleton global `_state_module.state`** : `_on_finished` est le callback de fin de `LoadWorker` (QThread) — en split-view, si l'utilisateur interagit avec l'autre panneau pendant le chargement en arrière-plan, le singleton global peut pointer sur le mauvais panneau au moment où le thread termine. `self._state` (capturé par l'instance `ArchiveLoader` à sa construction) est correct quel que soit le panneau actif.
- **Raisons d'une page ou d'un fichier illisible — `modules/qt/read_errors.py`** : le message brut de l'erreur (exception de zipfile, rarfile, tarfile, 7z, Pillow, ou texte de `entries.create_entry`) est **stocké tel quel** (`corruption_reason`, lignes « nom: message ») et **traduit seulement à l'affichage**, pour suivre un changement de langue : `read_error_text(raw)` reconnaît les causes courantes par motifs (`_CAUSES` : données abîmées, mot de passe, compression non prise en charge, fichier incomplet, format non reconnu, fichier vide, dimensions invalides ; `_TOO_LARGE_RE` pour « 4.20 Go > 500.0 Mo ») et rend une clé `messages.read_errors.*`, sinon `other` (« illisible (message technique) », tronqué à `_MAX_DETAIL`). `files_ignored_line(error, member_names)` reformule une ligne « nom: message » de « Fichiers ignorés » — seulement si le nom désigne un membre illisible (`unreadable_member_names(images_data)`, toutes les formes de `member_name_forms`) : les messages déjà traduits et les erreurs d'archive entière passent tels quels. Appelants : `tooltips_qt.get_tooltip_text` (info-bulle), `ArchiveLoader._on_finished`, `import_merge_qt.on_finished` (toutes ses erreurs sont des erreurs de membre : `member_names=None`). **Ajouter une cause** : un motif dans `_CAUSES` et sa clé dans les 46 langues (skill `add-translation`).
